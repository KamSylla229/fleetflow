Quatre choses à savoir avant de lire ce gabarit. 1. **Le dessin est un SVG maison, sans aucune bibliothèque.** Les trois axes, les villes et les camions sont tracés par static/js/carte.js dans un repère fixe de 1000 × 700, que le navigateur étire à la place disponible. Rien ne vient du réseau : ni bibliothèque, ni tuile, ni police. 2. **La page est lisible sans JavaScript.** La liste de droite est rendue par Django : plaques, états GPS, vitesses, heures de relevé. Si le script ne tourne pas, il reste un tableau de suivi parfaitement utilisable. Le dessin, lui, n'est pas rendu deux fois — un dessin n'est pas une donnée, et le produire en gabarit *et* en JavaScript reviendrait à le maintenir deux fois. 3. **Toute la géométrie est projetée côté serveur**, par fleet/itineraires.py, et livrée en coordonnées du dessin. Le script ne sait rien de la latitude ni du cosinus : la projection n'existe qu'à un seul endroit, où elle est éprouvée sans base de données. 4. **json_script et non un {{ }} dans du JavaScript.** Le filtre produit une balise pour sortir de la chaîne. {% endcomment %} {% block titre %}Carte de la flotte — FleetFlow{% endblock %} {% block titre_page %}Carte de la flotte{% endblock %} {% block sous_titre %} {% comment %} Les compteurs portent un data-carte-compteur : le script les récrit sans recharger la page, comme les cartes du tableau de bord. {% endcomment %} {{ compteurs.en_route }} en route · {{ compteurs.a_arret }} à l'arrêt · {{ compteurs.sans_signal }} sans signal · relevé à {{ mesure_le }} {% endblock %} {% block actions %} Alertes Tableau de bord {% endblock %} {% block contenu %} {% comment %} Les positions initiales voyagent avec la page, et non par un premier appel à l'endpoint : les camions sont donc en place dès l'ouverture, sans dixième de seconde de carte vide, et sans une requête HTTP de plus.
